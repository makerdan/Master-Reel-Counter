## Input and caller contract

New specs retain their existing Unified fields and add one `regression` object:

| form | Required fields beyond `form`, `material`, `rationale` |
|---|---|
| `normal` | `covers`, `testLocation`, `assertion` |
| `na` | `category`, `scenario`, `evidence`, `alternatives`, `residualRisk` |
| `self` | `testLocation`, `assertion` |
| `excluded` | `category` |

`material` is an explicit boolean assessment; `rationale` explains actual scope.
Normal fields identify a concrete scenario, project-relative test file/case and
detecting assertion. A future file is permitted; delivery must prove it exists
and runs. Existing-test reuse needs the actual case/assertion, not a bare directory.
N/A categories are `real-timing`, `external-service`, `visual`, `removed`.
Exclusions are `additive`, `cosmetic`, `internal`, `deletion-marked`.
Material work cannot use self-satisfaction or exclusion. Extra/mixed fields,
placeholders, injected declaration sections and malformed paths are rejected.
`deferred` is represented as unsupported and rejected explicitly: no supported
commitment/ownership/authorization route has been installed. Deliver the guard
here rather than invent approval evidence.

The renderer emits the canonical normal, N/A or self-satisfying form. Excluded
work retains its rationale in sealed metadata and does not emit a fake normal
section. Whole-file plan seals also reject injected or changed declarations.

Actual entrypoints:

- `npm run gate:draft -- --spec <file>` / `prepareDraft`: read-only complete draft.
- `gate:new` / `provision`: current contract selected internally, existing writer.
- `gate:amend` / `amend`: validates candidate before publishing a new revision.
- `gate:guard` / `guard`: validates recorded contract, plan and classification.
- `gate:run` / exported `run`: invokes the same guard before workloads and after
  execution; task-context npm tier entrypoints still delegate through the facade.
- Merge guard preserves prior history and checks referenced Guard snapshots.

No automatic `--fix-stub` route is installed. No API claims native Start/editor
interception. Native approval, cancellation and scope remain Agent responsibilities.
The Agent must emit the classification announcement, assess semantic adequacy

## Structural checks versus accountable assessment

The parser cannot determine whether `material: false` is truthful or whether an
assertion actually reaches the responsible layer. Before admission, the Agent
must inspect scope and each proposed check. Examples assessed for this migration:

- A frontend stale-response repair with only a backend status-code assertion is
  inadequate despite structurally valid fields: require a frontend ordering test.
- A parser repair labelled “test-only” changes enforcement: normal guard needed.
  The two new integration cases supply normal coverage here.
- A harmless comment-only edit may be excluded; a DELETE title removing surviving
  behavior cannot be excluded on the title alone.
- “Race” or “no screenshot” alone is not N/A: evaluate deterministic ordering,
  boundary tests and actual visual tooling before accepting the exception.
- A previously implemented case is reusable only if its assertion catches the
  actual recurrence. Fields and paths alone do not establish delivery.

These are executor assessment rules, not claimed automated semantic tests.
The CLI rejects duplicate raw JSON keys before using specification inputs, so
JSON.parse's last-key-wins behavior cannot hide duplicate declaration fields.
The structural checker also rejects mixed/extra fields and duplicate sections.
